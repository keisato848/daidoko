# 文言と実装の食い違いを探す

**このアプリは実際に「嘘」を 2 件出荷した。** どちらもコードは正しく動いていて、
説明だけが取り残されていた。テストも型も lint も通る種類の壊れ方なので、
人が読む以外に見つける手が無い。

## 実例（これと同じ型を探す）

**① コーチマークが指す先と文言がずれた**

`#219` で買い物リストをボトムタブへ出し、空いたヘッダ枠に設定を置いたとき、
`ref={cartRef}` を新しい Pressable にそのまま付け替えた。結果、**設定の歯車を
ハイライトしながら「買い物リスト・在庫・レシート読み取りはこのカートから」と
説明する**状態が 1.12.2 まで出荷された。画面にカートは無い。

- `key: 'cart'` / `cartRef` / `t('home.coach.cartTitle')` の三者は揃っていたので、
  文法的には何も壊れていない
- 壊れたのは「`cartRef` が指す DOM が何になったか」だけ

**② 出荷済みの機能を「今後追加予定」と表示し続けた**

クラウド同期は動いていた（`_layout.tsx` の `initSync()`・`family.tsx` の共有セクション）
のに、設定の行だけ `enabled: false` / `statusLabel: t('settings.comingSoonStatus')` の
まま残っていた。**データを守る話を探しに設定を開いた人が、アプリ自身の説明を読んで
「同期は無い」と結論する。**

## 探し方

1. **コーチマークの三者一致**
   - `useCoachMarks(...)` の呼び出しを全部見る（`Grep` で `useCoachMarks`）
   - 各定義の `ref:` が指す変数名 → その変数が `ref={...}` で付いている JSX 要素 →
     その要素が**実際に何なのか**（アイコン名・`onPress` の遷移先・`accessibilityLabel`）
   - それを i18n の `title` / `text` と突き合わせる。**要素の実体と文言の主語がずれていたら報告**
   - ref 変数名そのものが実体とずれている場合も報告する（`cartRef` が設定を指す等）。
     名前がずれたままだと同じ事故が再発する

2. **「今後追加予定 / coming soon / 準備中 / 未対応」を名乗る箇所**
   - `Grep` で `comingSoon` / `準備中` / `今後追加` / `enabled: false` を拾う
   - それぞれについて、**その機能が本当に未実装か**をコードで確かめる。
     サービス層に実装があり画面から到達できるなら「嘘」として報告

3. **i18n の死にキー**
   - `src/i18n/locales/ja/*.ts` のキーを列挙し、`t('<key>')` の参照が 0 件のものを探す
   - 死にキーそのものは無害だが、**「使われていない文言が残っている」＝
     画面が変わったのに文言が追随していない痕跡**なので、周辺を疑う手がかりになる

4. **空状態・ヘルプの説明が現在の導線と合っているか**
   - `EmptyState` の説明文、`settings.coach.*`、「使い方」系の文言
   - 「…はここから」「タブの…」のような**場所を指す表現**を全部拾い、実際の場所と照合

## 規律

- **画面を実際に開かずに判断すること**（このエージェントは読むだけ）。断定できないものは
  「疑わしい・要目視」として severity を下げて報告する
- 意図的な表現は報告しない。例: 「AI が推定した値です」のような注意書きは
  実装と食い違っていない
- **報告には必ず「文言」と「実際にそこにあるもの」を並べて書く。** 片方だけでは
  読み手が判断できない
- 見つからなければ「見つからなかった」と書く。水増ししない
