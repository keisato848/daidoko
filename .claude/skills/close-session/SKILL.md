# セッションを閉じる

**目的**: 出したものが実装と食い違ったまま残らないこと、外に出したもの（鍵・検証ビルド・
平文 HTTP 許可）を戻し忘れないこと、次のセッションが状況を再構築せずに済むこと。

`record-finding` は「分かったことを**どこへどう**書くか」。この Skill は
「**閉じるときに何を確かめるか**」。記録の書き方はあちらへ委譲する。

---

## 1. 触ったものの棚卸し

```bash
git status --short                       # 未コミットの取りこぼし
git log --oneline origin/main..HEAD      # このセッションで積んだもの
git status -sb | head -1                 # upstream がどこを指しているか
```

- **未 push があると PR のマージがガードで止まる**（`docs/開発ハーネス.md` §2）。
  ここで push まで済ませる
- `git status -sb` の 1 行目が `<feat>...origin/main` になっていたら upstream が
  main を向いている（worktree で `checkout -B` した副作用）。
  `git branch --set-upstream-to=origin/<feat> <feat>` で直す

## 2. 分かったことを残す（→ `record-finding`）

Stop フックの督促を待たずに先回りする。**本当に無ければ「記録すべき発見は無かった」と
報告に明記**して終える（黙って終えない）。

このセッションで**手が止まった場所**を思い出すのが早い。20 分溶かした所には
たいてい記録すべきものがある。

## 3. ドキュメントと実装の整合性

**機能を移設・置換・削除したときは必ず回す。** 設計書は移設に追従しない。

### 3-1. 機械的な突き合わせ

```bash
# docs / Skill が挙げるファイルが実在するか（リネーム・削除の取りこぼし）
grep -rhoE '\bapps/(mobile|server)/[A-Za-z0-9_./()\[\]-]+\.(ts|tsx|js|mjs)' \
  docs/*.md .claude/skills/*/SKILL.md | sort -u \
  | while read f; do [ -e "$f" ] || echo "MISSING: $f"; done

# ルータに生えているエンドポイントが docs に載っているか
grep -oE "Router\.(post|get|delete|put)\('/[a-z:./-]+'" apps/server/src/routes/*.ts | sort -u
grep -n "/api/v1/" docs/アーキテクチャ設計.md
```

> エンドポイントの grep は **chain 形式（`.post(` が行頭）と `xxxRouter.post(` の両方**を
> 拾うこと。片方だけだと実在するルートを「未実装」と誤判定する（2026-08-24 に
> `/sync/push` `/sync/pull` を取りこぼした）。

```bash
# 誰からも import されていないモジュール（**偽陽性が多い。必ず個別に確かめる**）
cd apps/mobile && for f in $(find src -name "*.ts" -not -path "*__tests__*"); do
  base=$(basename "$f" .ts)
  hits=$(grep -rl "from '.*/$base'" src app --include=*.ts --include=*.tsx 2>/dev/null \
         | grep -v "__tests__" | grep -v "^$f$" | wc -l)
  [ "$hits" -eq 0 ] && echo "UNUSED?: $f"
done
```

偽陽性の典型（**これらは死んでいない**）:

- `*.web.ts` / `*.ios.ts` … Metro のプラットフォーム解決。拡張子なしで import される
- テストと `scripts/` からしか使われないもの（fixtures・期待値の表）

本当に死んでいたら、**消してから設計書を直す**。残したまま「未使用」と書くと必ず腐る。

### 3-2. 目で見る突き合わせ（grep で出ない）

機能を置き換えたら、**その機能を語っている文を全部**洗う。よく残るもの:

| 種類                   | 例（2026-08-24 に実際に食い違っていた）                                           |
| ---------------------- | --------------------------------------------------------------------------------- |
| プラットフォーム対応表 | 「iOS 非提供」のまま（AI 化で提供になった）— `docs/リリース手順.md`               |
| 無料枠・課金を通す導線 | 経路が 4 つのまま（5 つ目が増えていた）— `docs/フリーミアム設計.md`               |
| 画面一覧の説明         | 「カメラから文字認識」のまま — `docs/画面設計.md`                                 |
| 採用ライブラリ         | **依存に無いライブラリが載っていた** — `CLAUDE.md` §3                             |
| エージェント番号の割当 | 退役したエージェントの枠を別のものが使っていた — `docs/マルチエージェント設計.md` |

`CLAUDE.md` §2 の設計書索引を上から眺めて、**触った機能に触れている文書**を選ぶ。

## 4. 後始末（外に出したもの・端末に残したもの）

**忘れやすい順**に並べてある。該当するものだけ。

| 出したもの                    | 戻し方                                                                 |
| ----------------------------- | ---------------------------------------------------------------------- |
| 検証で入れた API キー(BYOK)   | アプリの「自分のAIキー」→ 削除。**利用者のキーを端末に残さない**       |
| `usesCleartextTraffic="true"` | `AndroidManifest.xml` から外す（平文許可のビルドを配らない）           |
| `adb reverse`                 | `adb reverse --remove-all`（本番構成の検証を壊す）                     |
| 画面・電源の設定              | `svc power stayon false` / `screen_off_timeout` を元の値へ             |
| Wi-Fi・機内モード等           | 検証で切り替えたなら戻す（**戻せない操作は先に申し送る**）             |
| ローカルサーバー・エミュ      | 止める。生き残ると次のセッションが古い版を掴む（`emulator-verify` §4） |
| scratchpad の一時ファイル     | **鍵やトークンを書いたものは消す**                                     |

**端末に検証ビルドが入ったままなら、必ず申し送る。** `EXPO_PUBLIC_*` を仕込んだビルドは
無料枠 0・テスト広告・サンプルデータ入りで、普段使いには向かない。Play 版へ戻す必要がある。

## 5. 申し送り（報告に必ず書く）

- **未完了**と、その理由（判断待ち / ブロック要因 / スコープ外にした）
- **利用者の判断を待っているもの**（選択肢と、こちらの推奨）
- **配信されたか**。main にマージしただけなら「**アプリはまだ配信されていない**」と明記する
  （サーバーのデプロイとアプリのリリースは別物）
- 触った端末・サーバーの状態（§4 で戻せなかったもの）

## 6. 品質ゲート（PR を出すなら）

```bash
pnpm -r typecheck && pnpm -r lint && pnpm -r test
```

pre-commit が Prettier を掛けるが、**Windows では改行コードだけ書き換わって
無関係なファイルが大量に `M` になる**ことがある。`git diff --cached --stat` で
**実際にコミットされる差分**を確認してから積む（内容差分ゼロのファイルは commit に出ない）。
