# Apple Ads の $100 クレジットを使えるか、画面で確認する

> **やることは「見るだけ」。** 判定は**税金 ID 欄に必須マークが付いているか**の一点。
> 背景と根拠は `docs/store/広告出稿の検討-2026-08-27.md`。
> **サインインと規約同意は本人にしかできない**（Apple Account の 2FA・法的合意・カード登録のため）。

## 【結論】税金 ID は **「スキップ」できる**（2026-08-27 実測）

**壁は存在しなかった。ただし「欄が無い」のではなく「飛ばせる」が正しい。**

| 画面                                                                  | 税金 ID      | 住所         |
| --------------------------------------------------------------------- | ------------ | ------------ |
| サインアップ `ui.ads.apple.com/signup/create-account`                 | **欄が無い** | **欄が無い** |
| **アカウント作成後** `app-ads.apple.com/cm/basic/app/businessdetails` | **ある**     | **ある**     |

**後者に「スキップ」ボタンはあるが、スキップすると広告を配信できない**（2026-08-27 利用者確認）。
つまり**実質は必須の画面**で、「スキップ」は後回しにできるだけ。

**そして、その画面の中で税金 ID は「任意」だった**（2026-08-27 利用者が画面で確認）。

→ **結論: 商取引詳細は必須。ただし税金 ID は任意。**
**開業届もインボイス登録も不要で、撤退の分岐は発生しない。**

埋めるのは **法人名（= 姓名。`Kei Sato`）/ 法人のステータス「いいえ」/ 住所（自宅）**の 3 つ。

住所欄の説明（ツールチップ・逐語）:

> 法的に登録されており、納税居住者とみなされているビジネスの住所です。多くの場合、
> 主たる事業所または本社が所在する国／地域、または会社の公式なレターヘッドに記載された
> 国／地域が該当します。

→ 事業所を持たない個人には**自宅住所**。ただし**スキップできるので、入れなくてよい**。

**支払い方法の登録で請求先住所を求められる可能性は残る**（そこは別画面）。

> **同じ点で 2 回外した。**
> 1 回目: サインアップのフォームに無いことをもって「Basic には税金 ID 欄が無い」と書いた
> → **アカウント作成後の画面に出てきた**
> 2 回目: 「スキップボタンがあるから入力不要」と書いた
> → **スキップすると広告が配信できない**
>
> **画面に何が「見えるか」だけで結論しない。** その先で何が起きるかまで確かめる。
> ボタンが押せることと、押して目的が果たせることは別。

## （旧・誤り）2026-08-27 に実画面で確認 — Basic に税金 ID 欄は無い

**壁は存在しなかった。** `ui.ads.apple.com/signup/basic/landing` → `/signup/create-account` の
実画面で確認した結果:

| 項目                             | 実際                                                             |
| -------------------------------- | ---------------------------------------------------------------- |
| **税金 ID**                      | **欄そのものが無い**                                             |
| **所在地（住所）**               | **欄そのものが無い**（支払い方法の登録時に聞かれる可能性は残る） |
| 法人のステータス（法人ですか？） | **質問自体が無い**                                               |

Basic のアカウント作成で聞かれるのは **取引先名 / 国または地域 / 通貨 / タイムゾーン /
法人名 / エージェントか / 主要連絡先（氏名・電話・メール）/ メール通知**だけ。

**Apple 自身が個人を明示的に想定している。** 法人名の欄の説明文が逐語で:

> ビジネス名または法人名を入力してください。**個人として運営している場合は、姓名を使います。**

これで「登記していない個人が法人名に何を入れるか」も確定した（＝**姓名**。推論ではなくなった）。

**「税金 ID が必須なら撤退」という分岐は発生しない。開業届もインボイス登録も不要。**

Apple のヘルプが列挙していた「商取引の詳細」4 項目は **Advanced 側の話**だったと考えられる。
**ヘルプの項目一覧を Basic にも当てはめたのが誤りだった。**

以下は判定前の記録（同じ調査をやり直さないために残す）。

---

## （判定前）なぜ画面を見ないと分からなかったのか

公開文書では**ここまで**確定している。

- Apple が税金 ID の提供を求める国は**8 つ**（豪・ブラジル・コロンビア・印・NZ・比・韓・台）。
  **日本は入っていない**（https://ads.apple.com/jp/taxes 全文確認・2026-08-27）
- 日本の項は**消費税の課税方法の話だけ**で、番号の要求は一言も無い
- 設定ページは 4 項目を列挙するのみで**必須／任意を書き分けていない**
- **個人事業主は想定利用者**（「個人事業主の場合は『いいえ』を選択します」と明記）

→ **法的義務が無いことと、フォームが空欄を通すことは別。** 画面でしか分からない。

## 手順

### 0. 前提（確認済み・作業不要）

- iOS 版は App Store で販売中（App ID `6800964382`・1.11.0・Food & Drink・評価 0 件）
- クレジットの適格条件「ASC の登録アカウントホルダー＋販売中のアプリ 1 本以上」は**クリア済み**

### 1. **Basic から入る**（順番が重要）

https://ads.apple.com/jp/app-store/basic → サインイン。

> **Advanced を先に作らないこと。**
> 「Advanced を作りかけて途中で Basic に切り替えようとするとエラーになる」と Apple が明記している。
> 予算管理の面でも Basic が安全（月予算に上限が効く・インストール課金）。
> Advanced は**予算上限が無い**。

**App Store Connect と同じメールアドレスの Apple Account** でサインインすること
（電話番号のみの Apple Account は不可）。

### 2. 見るもの — **ここが判定の全て**

「商取引の詳細」の画面が出たら、**税金 ID 欄に必須マーク（\*）が付いているか**を見る。

| 見えたもの                             | 意味     | 次                 |
| -------------------------------------- | -------- | ------------------ |
| 税金 ID が**任意**（または欄が出ない） | **通る** | 3 へ進む           |
| 税金 ID が**必須**                     | **詰み** | **止まる**（下記） |

### 3. 入力（任意だった場合）

| 欄               | 入れるもの                                                                   |
| ---------------- | ---------------------------------------------------------------------------- |
| 法人のステータス | **いいえ**（個人事業主）                                                     |
| 法人名           | 法的氏名。**App Store の販売元表示 `Kei Sato` と揃える**                     |
| 税金 ID          | **空欄**                                                                     |
| 所在地           | 自宅住所（**公開されない** — 下記）                                          |
| 通貨             | **JPY**                                                                      |
| 支払い方法       | 個人の Visa / Mastercard / Amex。**プリペイド・ギフトカード・PayPal は不可** |

### 4. $100 クレジットの取りこぼし（**一度きり・やり直し不可**）

Apple の逐語:

> "If you link a campaign group instead of your top-level account, the credit won't be applied."

**キャンペーングループではなく、最上位の App Store Connect アカウントにリンクする。**
リンク先を選ぶ画面が出たら、ここで手を止めて確認すること。

付与されたら**有効期限を確認**（公開ヘルプに記載が無く、未確認）。

### 5. 配信設定

- **EU / 英国は外す**（既存方針。そもそも両ストアにアプリが無いので出稿できないはず）
- 日本（必要なら米国も）のみ

## 止まる条件

**税金 ID が必須だったら、そこで終わり。撤退が正解。**

理由: 日本の個人が持てる税金 ID は**インボイスの登録番号だけ**で、それを得るには
**課税事業者になる**必要がある（＝消費税の納税義務）。**$100 のための代償として割に合わない。**

**「開業届を出せば解決する」は誤り。** 開業届は所得税法 229 条の届出にすぎず、
**番号は交付されない**。法人番号は個人に永久に出ない。

**マイナンバーは絶対に入力しない。** 番号法 15 条（提供の求めの制限）・20 条（収集等の制限）が
法定の場合を除いて「何人も」求めること・収集することを禁じている。広告出稿は該当しない。
**求められたら、それ自体がおかしい。止めて報告すること。**

## 住所について（Play のときとは違う）

**登録はするが、公開はされない。**

- Apple Ads の広告リポジトリ（EU DSA 39 条）が公開するのは**氏名レベルで、住所欄が無い**
- **iOS 版は EU/英国のストアに無い**（de/fr/ie/gb で `resultCount=0`・2026-08-27 実測）ので、
  そもそもリポジトリに載る経路が無い
- 製品ページに住所が出るトリガーは Apple Ads ではなく **DSA の取引者(trader)要件**。EU 配信をしない限り引かれない

ただし**「絶対に公開しない」という明文の保証は取れていない**（規約に「Apple は情報を公表または
開示する義務を負う場合がある」という包括条項が実在。住所への言及は無い）。

## これは「30 分で撤退」ではない

アカウント作成は**規約への同意＋法的氏名・住所・カード登録**を伴う。規約に
「正確・最新・完全な情報（住所、支払情報、**関連する税務情報（納税者番号や証明書等を含む）**）を
提供することに同意する」という条項が実在する。
**作成後に Apple が事後的に番号提出を求めてくる経路は、確率は不明だが存在する。**

## 報告してほしいこと

1. **税金 ID 欄に必須マークが付いていたか**（付いていなければスクリーンショット 1 枚）
2. 商取引の詳細の画面が Basic でも出たか
3. **$100 クレジットが実際に付与されたか**・**有効期限**
4. 途中で出た警告・確認ダイアログの文面

## やらないこと

- **マイナンバーの入力**
- **課税事業者登録・開業届**（$100 のためにやることではない）
- **EU / 英国への配信**
- **Advanced を先に作る**
- **クレジットを超える自腹の追加投入**（結果を見てから判断する）

## 規約で押さえること（2026-08-27 に全文を読んだ・発効日 2026-07-28）

### ⚠ 自分の広告をタップしない（第 6 条 g-VI）

> お客様は**自動的、不正、もしくはその他無効なクリック、インプレッション、またはその他のアクションを
> 生成してはならず**、また、これらを生成することをいかなる者に対しても承認してはならない

**動作確認のつもりで自分の広告をタップすると、課金されるうえに規約違反になりうる。**
広告枠の見え方を確かめたいときは**見るだけ**。家族・知人に頼むのも同じく駄目。

### ⚠ 税務情報の提供義務は契約に入っている（第 4 条）

サインアップの**フォームに税金 ID 欄は無い**（実測）が、契約では:

> 会社名、Eメールアドレス、住所、会社の支払い情報、**関連する税関連情報（納税者登録番号、
> 税務登録証明書などを含む）**...を含む、正確、最新かつ完全な情報を提供することに同意する
>
> 提供、更新、および維持することを怠った場合、いつでも、本サービスへのアクセスまたは
> 本サービスの利用が**一時停止または終了**される可能性がある

**求められる可能性は残る。** 求められた時点で、日本の個人には出せる番号が無い（→ そこで撤退）。

### ⚠ Apple との関係を公開の場で書くには書面承認が要る（第 6 条 i）

> 本サービスもしくはお客様によるその利用、本サービス規約、広告コンテンツ、または
> **お客様のAppleとの関係に言及または関連するあらゆるプレスリリースまたは発表は、
> Appleによる書面での承認を受けなければならない**

**「Apple Ads を使ってみた」を LP・note・X に書くのは、文面上この条項に当たる。**
（このリポジトリは private なので対象外）

### その他

| 第 7 条 k | 支払遅延 → 利息（基準金利 +1%）＋ **回収費用（弁護士費用を含む）** を負担                    |

| 第 4 条   | 請求書・通知は**英語**で届く。英語を読めることに同意させられる                               |
| 第 10 条  | 広告が第三者の権利を侵害した等の場合、**上限なしで Apple を補償**する                        |

### 住所について

**開示条項（第 6 条 d）に住所への言及は無い。**「本サービスの利用・広告コンテンツ・
キャンペーンに関する情報を公開または開示する義務を負う場合がある」までで、住所は対象外。
第 4 条で住所は収集されるが、用途は**本人確認の検証**で、共有先は秘密保持義務を負う
Apple 認定ベンダー／外部契約者。**公開経路は規約からも読み取れない。**

### $100 の有効期限（promo-terms・発効日 2026-08-14）

> 本オファーに**有効期限日が設定されている場合**、その本オファーの未利用分も当該日に有効期限切れとなります。
> 本オファーの未利用分は、**お客様の本アカウントの終了**...の時点で、自動的に有効期限切れとなります。

**日数の記載は無い。** 期限の有無はオファー個別。**アカウント画面で確認するしかない。**
譲渡不可・現金化不可。不正取得や規約違反の場合は取り消される。
