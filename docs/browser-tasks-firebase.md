# ブラウザ操作セッションへの依頼 — Firebase（FCM）のセットアップ

> 別セッション（ブラウザ操作あり）に渡すプロンプト。
> 実行者は `.claude/skills/console-browser-ops/SKILL.md` を先に読むこと。
> 完了したらこのファイルは削除してよい。

## 背景（3 行）

- 「だいどこ」は Play / App Store で公開中（1.11.0）。家族でレシピと買い物・在庫を共有する同期機能が入っている
- **家族の誰かが変更しても通知が飛ばない。** アプリとサーバーのコードは完成しているが、
  **FCM が未設定**で端末が Expo Push トークンを取得できない（`sync_devices.expo_push_token` が NULL のまま）
- **必要なのは Firebase プロジェクトを 1 つ作って、設定ファイルを 2 つ取り出すことだけ**

## 費用（先に確認してほしいこと）

**この作業では課金は発生しない。** Cloud Messaging しか使わない。

- Firebase の Spark（無料）プランのままにする
- **請求先アカウントを紐づけない**。「アップグレード」「Blaze」の導線が出ても進まない
- Firestore / Functions / Storage / Hosting などは**一切有効にしない**

もし途中で**支払い情報の入力を求められたら、そこで止めて利用者に報告すること。**
FCM で課金を求められることは無いので、求められた時点で何かがおかしい。

## A. Firebase プロジェクトを作る

1. https://console.firebase.google.com/ → **プロジェクトを追加**
2. 名前は `daidoko`（既に同名があれば `daidoko-app` など。**利用者に確認**）
3. **Google アナリティクスは「有効にしない」**（下の「やらないこと」を参照。ここは重要）
4. 作成後、**プロジェクト ID を控える**（報告に使う）

> 既存の Google Cloud プロジェクトに Firebase を足す形でも動くが、**迷ったら新規作成でよい**。
> 既存に足すと、そのプロジェクトの他の設定（Gemini API のキーなど）と権限・課金が同じ器に乗る。

## B. Android アプリを登録して `google-services.json` を取る

1. プロジェクト概要 → **Android** アイコン
2. **Android パッケージ名: `com.daidoko.app`**
   - **一字でも違うと、ビルドは通るのに通知だけ来ない**（原因がアプリ側に見えて、切り分けに時間が溶ける）
   - コピーして貼ること。手打ちしない
3. アプリのニックネーム・SHA-1 は**空のままでよい**（FCM だけなら不要）
4. **`google-services.json` をダウンロード**
5. 以降の SDK 追加手順（gradle への追記など）は**画面の指示に従わなくてよい**。
   アプリ側の配線はこちらで行う。「次へ」で飛ばして完了させる

## C. FCM へ送るための鍵（サービスアカウント）を取る

1. 歯車 → **プロジェクトの設定** → **サービス アカウント** タブ
2. **「新しい秘密鍵を生成」** → JSON をダウンロード
3. これは **Firebase Admin SDK の秘密鍵**。厳重に扱う（置き場所は D）

> **この鍵を使うのは Expo（EAS）であって、だいどこのサーバーではない。**
> サーバーは Expo Push（`exp.host/--/api/v2/push/send`）へ投げるだけで、FCM へ送るのは Expo 側
> （`apps/server/src/routes/sync.ts`）。**Railway の環境変数には入れない。**
> EAS への登録は秘密鍵のアップロードなので**ブラウザ操作でも代行しない**（`console-browser-ops` §1）。
> 取り出して D に置くところまでが依頼範囲。

## D. ファイルの受け渡し

**この 2 つのファイルは、リポジトリに絶対に入れない**（API キー・秘密鍵を含む。gitignore 済み）。

- **同じ Windows マシンで作業しているなら**: 2 つとも `C:\secure\` に置く
  - `C:\secure\google-services.json`
  - `C:\secure\firebase-admin-<プロジェクトID>.json`（名前は何でもよい。報告で伝える）
- **別のマシンなら**: ファイルを利用者に渡し、`C:\secure\` に置いてもらう

## 完了したら報告してほしいこと

1. **Firebase プロジェクト ID**
2. B-2 で登録した**パッケージ名**（`com.daidoko.app` と一致しているか。実際に画面で見た文字列）
3. Google アナリティクスを**有効にしていないこと**
4. 2 つのファイルの**置き場所**
5. 途中で出た警告・確認ダイアログがあれば、その文面

## やらないこと（境界）

- **Google アナリティクスを有効にしない。** 有効にして SDK を入れると、アプリが解析データを
  収集することになり、**Play のデータセーフティと App Store の App Privacy を書き換える必要が出る**
  （2026-08 に審査を通したばかり。申告と実装が食い違うと公開が止まる）
- **AdMob との連携をしない**（2026-08-26 利用者決定）。連携自体は無料で無害だが、
  SDK を入れるまで見えるものが増えないので、いま繋いでも得るものが無い
- **請求先アカウントを紐づけない。Blaze へアップグレードしない**
- **Firestore / Functions / Storage / Hosting / App Check などを有効にしない**
- **iOS アプリを登録しない**（iOS の通知は APNs 経由で、この作業の対象外）
- 秘密鍵・設定ファイルを**リポジトリやチャットに貼らない**（置き場所だけ伝える）
- 上記 A〜D 以外のコンソール設定の変更

## このあと（メインループ側でやること・依頼不要）

`app.json` に `android.googleServicesFile` を配線 → **`--prebuild` 付きでビルド** →
実機で確認（`Default FirebaseApp failed to initialize` が消える／`expo_push_token` が入る／
別端末の変更で通知が届く）。手順は `docs/fcm-setup.md`。

**`eas credentials -p android` での FCM v1 鍵の登録は TTY が必要**なので、
ブラウザ操作では代行できない。利用者かメインループが端末で実行する。
