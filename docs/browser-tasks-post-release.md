**手順**

2. **「このバージョンの新機能」**（`What's New`）を入れる。ja / en の文面は私が
   `docs/store/release-notes-1.11.0.md` に置いておくので、そこからコピーする
3. **ビルドを選択**（TestFlight に上がっている 1.11.0 のビルド）
4. **App Privacy（栄養ラベル）を更新** ← 今回いちばん重要
   - クラウド同期でサーバーに**保持する**ものが増えたので、Play のデータセーフティと同じ内容に揃える
   - 「ユーザーコンテンツ」= レシピ・買い物・在庫 → **App の機能** / ユーザーに**紐付けない**（アカウントレスなので identity と結びつかない）
   - 「識別子」= 端末のランダム ID・プッシュトークン → **App の機能** / ユーザーに紐付けない
   - **氏名・メール・電話番号・住所は一切収集しない**（アカウントを作らない設計）
   - 判断に迷ったら、直前に更新した Play のデータセーフティ申告と読み比べて揃える
5. 「審査へ提出」→ 輸出コンプライアンスは `ITSAppUsesNonExemptEncryption: false` で自動回答済み
6. 審査は 1〜3 日

**注意**: EU/英国は配信対象外のまま（取引者申告の回避・方針は `docs/リリース手順.md` §7）。**配信国を触らないこと。**

## B. Play Console — データセーフティの再確認

私が 1.11.0 を提出した後、**申告が「審査中」のままになっていないか**を見てください。

- アプリのコンテンツ → データセーフティ → ステータスが「承認済み」なら何もしない
- 「変更を審査に送信」が未実行のまま残っていたら、内容を確認したうえで送信（**ユーザー承認が必要**）

**申告とアプリの中身が食い違うと公開が止まります。** 1.11.0 は同期を含むので、申告が旧内容（エフェメラルのみ・削除リクエストなし）に戻っていないか必ず確認してください。
