## 3-2. 実装側の進め方（2026-09-18 追記・待ち時間の見通し）

利用者の判断で「**本番リリースに影響しない範囲で Track C（献立の家族共有）まで一気に完成させる**」方針になり、Windows 側は並列で進めている。波ごとの対応:

| 波                 | 実装側でやること                                                                            | **あなたの素材がどこで撮れるようになるか**         |
| ------------------ | ------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| Wave 1（着手済み） | 相談のエージェント化（実機検証 → マージ）／献立の同期拡張／一括生成のジョブ基盤（サーバー） | 掲載文 §1-5「AI と相談しながらつくる」の裏が取れる |
| Wave 2             | **献立の週ビュー UI**／一括生成の枠対応／ジョブのモバイル配線                               | **スクショ 1・2 枚目／動画カット 3・5**            |
| Wave 3             | Android ウィジェット → iOS ウィジェット → 背景更新                                          | **スクショ 7 枚目／動画カット 8**                  |

**日数の見積もりは出していない**（設計書の人日見積もりは実績の 5〜20 倍過大だったため）。Wave 2 に入ったら Windows 側から連絡する。

### あなたに来る可能性が高い実装作業: iOS ウィジェット（PR-6）

ウィジェットの iOS 側は Xcode が要るため Mac 側の担当になる見込み。**まだ着手しないこと**（Android 側（PR-5）でデータの形が決まってからでないと二度手間）。設計は `docs/reviews/menu-track-design-2026-09-16.md` §6:

- 既存の `shopping-widget` ターゲットに `WidgetBundle` で追加する（新規ターゲットは作らない）
- **iPhone には「それ以上」の大きさが無い**（`systemExtraLarge` は iPad 専用）。受入基準は「**iPhone は 2 段まで**、3 段目は iPad のみ」に書き換え済み。Android の 3 段と同じにはできない
- push による背景更新（PR-7）も **iOS は配信保証が無い**ため「ベストエフォート・保証しない」に書き換え済み

### Wave 2 に備えて今やっておくと効くこと

Xcode の準備を進める際、**iOS シミュレータでストア用スクショが撮れる状態**（必要な機種・iOS バージョンの組み合わせ）まで確認しておくと、Wave 2 に入った時点ですぐ動ける。

## 6. 踏むと痛い罠（実測済み・繰り返さないこと）

### 6-1. 生成 AI でできること・できないこと（`gemini-generation-2026-09-17.md` の要約）

- **画像生成は使える**（`agy` の `generate_image`）。日本語の明朝体コピーも崩れない
- **動画・TTS・字幕は生成できない**（モデル一覧・ツール一覧に無い）
- **ストアのスクショを生成 AI に作らせてはいけない。** 実機スクショを `ImagePaths` で渡しても**描き直されて UI の漢字が誤字になる**（実測: 「玉ねぎの期**限**」→「期**服**」、タブバーの「在庫」「買物」が崩壊）。スクショは実機キャプチャ ＋ `sharp` 合成だけで作る
- 生成物の寸法はストア要求と一致しない（`AspectRatio` は比率のみ）。生成 → `sharp` リサイズを常に 1 セットで

### 6-2. 既存素材に見つかっている欠陥 3 件（README にも追記済み）

1. `extras/11-shopping-list.png` が **1080×2432**（AQUOS 実機）。他は 1080×2400 で、**混ざると `update-play-screenshots.mjs` の dry-run が止まる**
2. **en 側に `11-shopping-list` が無い** — 英語の買い物リストは一度も撮られていない
3. `12-fridge-to-recipe.png` の読み取り結果が**ほぼ全部調味料**（野菜も肉も無い）＝ §6 のデータセット設計の起点が成立しない

### 6-3. 共有資源の取り合い（Windows 側で実害が出た）

- メインの作業ツリーを複数セッションが共有すると、`packages/shared` や `node_modules/.bin` が**自分が何もしていなくても消える**ことがある（2026-09-18 被弾・`docs/開発ハーネス.md` §7-0 項目 5）
- エミュレータ（`emulator-5554`）も取り合いになる。**Mac 側に移した以上、Windows 側のエミュレータは触らない**

### 6-4. 語彙の出現数を減らさない（10-03 の効果判定の部分的な救済）

Q3 で主語を動かしたため 10-03 の判定は本来切り分け不能になるが、**掲載文に出る検索語の出現数を現行と同数以上に保てば部分的に救える**（けんじ案）。
Phase 1 の計測では**一語も減っていない**（献立 17→17、在庫 17→18 等）。**Phase 2 で文面をいじるときも必ず再カウントする。**

**混同注意**: 帯・動画字幕で「在庫」→「食材」に言い換えているのは**画像の中だけ**。**掲載文の「在庫」17 回は置換しない**（置換すると上の表が崩れる）。

### 6-5. 掲載文の動詞は、主語が「アプリ／AI」に読めないか毎回確かめる（**最も再発する**）

「撮れ**ば**在庫にな**り**…買え**ば**在庫に戻る」のような**自動で起きるように読める書き方**は、
`listing-ja.md` が**5 次にわたって直してきた掲載事故**（「確認してから在庫に追加」「自動で入るとは書かない」「タップで在庫へ」）。
実装は各段階に確認シート／選択シート／タップがある**手動の輪**なので、自動と読める文は虚偽になる。

**Phase 1 でも一度踏んだ**（自分で「AI が自動でやるとは書かない」と宣言した案の中に、その型の段落が混ざっていた。
ペルソナのけんじが実物と突き合わせて発見）。**何度でも再発する型**なので、文面を書いたら必ず
「この動詞の主語は利用者か、アプリか」を 1 文ずつ確認すること。主語を利用者にして書き直すのが正解。

同種の禁止表現（`刷新案` と `listing-ja.md` に既出）: 「撮るだけで作れる」「AI に何でも聞ける」「AI が家事をやってくれる」。
