# 週ビュー設計案（Gemini・gemini-3.1-pro-high・web 検索 4 回・2026-09-16）

> 出所: `harness:gemini-mode` の別の目。コードは読んでいない（ブリーフの事実のみ）。「推測」と書かれた箇所は未確認。

## 既存アプリの UI パターン（参考）

- 縦型タイムライン（リスト）型: 日付を縦にスクロール。モバイル幅で情報量を確保しやすい（参考: KitchenOwl https://github.com/KitchenOwl/KitchenOwl ）
- 横スワイプ・ページャー型: 1 画面 = 1 日または 1 週間、横スワイプで切替（参考: TimeTree https://timetreeapp.com/ ）

---

## 案 A: 献立タブの「縦型スクロール週ビュー」化

### 1. 置き場所と既存画面との関係

- 現在の `(tabs)/menu.tsx`（献立タブ）を「週ビュー」として全面改修
- ホーム（`index.tsx`）は現状維持（情報密度を保つため献立は置かない）

### 2. 1 日のセル（ASCII・360px）

```text
+------------------------------------+ (罫線: #2E2418)
| 9/18 (Wed)            🔄 by Papa   | <- 変更者(R26)
+------------------------------------+
| [夕食 / Dinner]                    | <- 時間帯(R27)
| 👑 ハンバーグ / Hamburg Steak      | <- 主菜(R20)
| ・ サラダ / Green Salad            | <- 任意枠
| ・ 味噌汁 / Miso Soup              |
+------------------------------------+
| [昼食 / Lunch]                     |
| 👑 炒飯 / Fried Rice               |
+------------------------------------+
(背景: #0A0805 / テキスト: #DCC9A8 / アクセント: #C9A16A)
```

### 3. 予定→実績（R25）

`doneAt` があればセル背景をわずかに暗く（または透明度を下げ）、主菜の横に「✅ Done」のゴールドバッジ。

### 4. 家族の変更（R26）

- セル内: 日付ヘッダー右端に「🔄 by [ユーザー名]」
- 通知: 既存の「黙って更新」に加え、`createdBy`（**推測**: サーバー側で誰の操作か取得できる前提）で「[ユーザー名] changed Thursday's menu」の push

### 5. 時間帯設定（R27）

有効な時間帯のブロックだけを縦に積む。夕食のみなら縦幅が短くなり一覧性が上がる。

### 6. 触るファイル

- `apps/mobile/app/(tabs)/menu.tsx`: リスト表示 → 週カレンダービュー
- `apps/mobile/app/calendar.tsx`: 月表示の調理記録としてそのまま残す（過去の月間実績の振り返りに特化）

### 7. 利点・欠点・要件対応

- 利点: (1) 縦スクロールだけで 1 週間を俯瞰、空き枠を見つけやすい (2) 3 食・3〜4 品でも縦に伸びるだけで崩れにくく、文字を大きくしやすい (3) `calendar.tsx` を壊さず役割分担が明確
- 欠点: (1) 3 食全部だと縦に長すぎ、木・金を見るスクロール量が増える (2) 「タイムライン」の印象が残りうる (3) 一括生成で大量に埋まると圧迫感

| 要件 | 対応   | 備考                               |
| ---- | ------ | ---------------------------------- |
| R19  | 満たす | 同期で画面更新                     |
| R20  | 満たす | 主菜を目立たせ任意枠を並列         |
| R21  | 満たす | 設定でブロック数を増減             |
| R22  | 満たす | 一括生成ボタンをヘッダーに（推測） |
| R23  | —      | UI 案のため影響なし                |
| R24  | 満たす | `doneAt` で同じセル上に            |
| R25  | 満たす | `doneAt` でスタイル切替            |
| R26  | 満たす | セルヘッダー＋push                 |
| R27  | 満たす | 表示ブロックの出し分け             |

### 8. 未決への依存

- 既存データ移行: 1 日 1 レシピを「夕食の主菜」にマッピングするフォールバック表示の検討が要る
- 通知頻度: 都度 push はスパムになる。「N 分変更が無ければまとめて」のデバウンスに依存

## 案 B: 横スワイプ型「ハイブリッド・週カレンダー」

### 1. 置き場所と既存画面との関係

- `calendar.tsx` を改修し「月間 / 週間」トグル付きのカレンダー画面に
- `(tabs)/menu.tsx` は廃止（またはリダイレクト）。タブ名を「プラン＆実績」等に変えて `calendar.tsx` と統合

### 2. 1 日のセル（ASCII・360px）

```text
[Mon] [Tue] [Wed(今)] [Thu] [Fri] [Sat] [Sun] <- 上部固定(タップ可)
---------------------------------------------
< 前の日                   (🔄 by Mama) 次の日 >
+-------------------------------------------+
| 🌙 夕食 / Dinner                          |
|                                           |
| 【👑 Main】                               |
| 鶏の照り焼き / Teriyaki Chicken           |
|                                           |
| 【🥗 Sub】                                |
| ・ ほうれん草のお浸し / Spinach Ohitashi  |
| ・ 味噌汁 / Miso Soup                     |
+-------------------------------------------+
```

### 3. 予定→実績（R25）

上部曜日バーの色が変わる（予定のみ＝グレー枠、`doneAt` でゴールド枠）。詳細カードにスタンプ風「✅ 完了 / Done」。

### 4. 家族の変更（R26）

- セル内: 詳細カード右上に「🔄 by [ユーザー名]」
- 通知: アプリ内スナックバー（**推測**: 既存にあるなら）または push「Mama updated Wed's menu」

### 5. 時間帯設定（R27）

詳細カード内で朝・昼・夕をタブ切替、または縦スクロール。

### 6. 触るファイル

- `apps/mobile/app/calendar.tsx`: 月/週切替、週表示の詳細コンポーネント追加
- `apps/mobile/app/(tabs)/menu.tsx`: 廃止（またはリダイレクト）

### 7. 利点・欠点・要件対応

- 利点: (1) 上部曜日バーで「カレンダービューで見たい」を強く満たす (2) 1 日の面積が広く、大きな文字や写真（推測）を載せやすい (3) menu と calendar が統合され導線が 1 か所
- 欠点: (1) 1 週間の全体像を 1 画面で見渡せない（1 日ずつ） (2) スワイプ・タップの手間が増える (3) タブ構造の変更で学習コスト

| R21  | 満たす       |                                                        |
| R22  | 満たす       | 曜日バー付近にボタン（推測）                           |

| R26  | 満たす       |                                                        |

### 8. 未決への依存

- 週の始まり: 曜日バーの並びに直結
