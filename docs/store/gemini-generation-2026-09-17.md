# 定額プランで使える生成機能の実物確認（2026-09-17）

> 依頼: 「Gemini 側で Omni 等を定額プラン内で使うなど、過去のリリースではできなかったこともできるようになるはず」
> （`docs/plans/2026-09-17-store-refresh-brief.md`）。
> **「Omni」が何を指すかは推測せず、`agy` の実物で確かめた。** 使えないものは「使えない」と書く。
> 環境: Antigravity CLI（`agy`）1.2.4 / Windows / Google アカウントの上限のみ（API キーは使わない・`useG1Credits: false`）。
> 確認日 2026-09-17。**ここに書いた挙動はすべて自分で実行して目で確かめたもの。** 再現コマンドを各節に付ける。

## 結論 3 行

1. **画像生成は使える。** `generate_image` ツールが `agy` から呼べる。日本語の見出しが崩れずに描画され、ブランド色（#0A0805 / #C9A16A）も指示どおり出る。これは過去のリリース時点からの実質的な変化。
2. **動画・音声・ナレーション・字幕の生成は `agy` からは使えない。** モデル一覧にもツール一覧にも存在しない。プロモ動画は従来どおり `promo-video` Skill（実機収録＋ffmpeg）で作る。
3. **ストアのスクリーンショットを生成 AI に作らせてはいけない。** 実画面を入力に渡しても**描き直され、UI の漢字が誤字になる**（実測: 「期限」→「期服」）。スクショは既存の `sharp` パイプライン（`scripts/generate-play-promos.mjs`）で決定的に合成する。

## 1. 何が使えるか（実測）

### 1-1. モデル一覧（`agy models`）

```
gemini-3.8-flash-{high,medium,low} / gemini-3.7-flash-{…} / gemini-3.6-flash-{…}
gemini-3.1-pro-{high,low} / claude-sonnet-4-6 / claude-opus-4-6-thinking / gpt-oss-120b-medium
```

**すべてテキスト（マルチモーダル入力）の LLM。** 画像生成モデル・動画生成モデル（Veo 系）・
音声合成モデルは一覧に**無い**。画像生成はモデル選択ではなく**ツール**として提供されている（§1-2）。

### 1-2. セッション内で呼べるツール（`agy` 自身に列挙させた・実測）

`run_command` / `read_url_content` / `replace_file_content` / `write_to_file` / `view_file` /
`list_dir` / `grep_search` / `find_by_name` / `define_subagent` / `invoke_subagent` /
`manage_subagents` / `send_message` / `ask_question` / `schedule` / `manage_task` /
**`generate_image`** / `search_web`

| 生成の種類         | 可否       | 根拠                                                 |
| ------------------ | ---------- | ---------------------------------------------------- |
| 画像生成           | **使える** | `generate_image`                                     |
| 動画生成           | 使えない   | 該当ツール無し・モデル一覧にも無し                   |
| 音声生成（TTS）    | 使えない   | 同上                                                 |
| 音声認識（字幕化） | 使えない   | 同上                                                 |
| Web 検索           | 使える     | `search_web`（ただし Claude 側にもあるので用は無い） |

再現:

```bash
agy --model gemini-3.8-flash-low -p "あなたが今この CLI セッションで使えるツールの一覧を、名前だけ列挙してください。（略）"
```

### 1-3. `generate_image` のパラメータ（実測）

| パラメータ    | 値                                                            | 備考                                    |
| ------------- | ------------------------------------------------------------- | --------------------------------------- |
| `AspectRatio` | `1:1`(既定) / `2:3` / `3:2` / `3:4` / `4:3` / `9:16` / `16:9` | **ピクセル数の直接指定はできない**      |
| `ImagePaths`  | ローカル絶対パスの配列・**最大 3 枚**                         | 編集・合成の参照として渡す（§3 の注意） |

実際の出力寸法（実測）: `1:1` → 1024×1024 / `16:9` → 1376×768 / `9:16` → 768×1376。
出力は PNG または JPG（呼び出しによって変わった）。**所要 10〜11 秒/枚。**

**ストアの要求寸法とは一致しない**（フィーチャーグラフィック 1024×500・スマホ用スクショ 1080×2400）。
生成物をそのまま提出することはできず、**必ず `sharp` でのリサイズ／トリミングの後段が要る**。

### 1-4. クォータ

1 セッション内で連続 4 枚生成してもエラー・警告は出なかった。**上限値そのものは画面に出ないため不明。**
「無制限」と読まないこと。まとまった枚数を回す前に、少数で試して警告の有無を見る。

## 2. 日本語の描画は実用水準にある（過去との差分）

`#0A0805` 背景に `#C9A16A` の明朝体で `きょうの献立、家族みんなで。` を生成させたところ、
**漢字・かな・句読点とも崩れずに描画された**（「献立」「家族」の字形も正しい）。
`写真を撮るだけで、レシピが完成。` を 16:9 の右半分に置いた例も同様。

これが意味すること: **日本語コピーを焼き込んだ帯・バナー・背景画を AI に作らせられる。**
従来は「日本語を画像生成に任せると崩れる」ため、文字はすべて `sharp` + SVG で後から重ねる前提だった。

**ただし §3 の制約があるので、「文字が出せる＝何でも生成でよい」ではない。**

---

## 3. スクリーンショットを生成 AI に作らせてはいけない（重要・実測で確定）

`ImagePaths` に実機スクショ（`05-menu-plan.png`・1080×2400）を渡し、
「**入力画像を一切改変せず**そのまま配置し、上にコピーを載せる」と強く指示して生成させた。

結果: **見た目は非常に良いが、UI の文字が描き直されて誤字になっていた。**
生成物を自分でクロップ・拡大して確認した実害:

| 元の表示                   | 生成物                     | 症状                                 |
| -------------------------- | -------------------------- | ------------------------------------ |
| 玉ねぎの期**限**が近いから | 玉ねぎの期**服**が近いから | 「限」のこざとへんが月に描き変わった |
| タブバー「在**庫**」       | 崩壊した別字               | 旁が実在しない字形に                 |
| タブバー「**買**物」       | 崩壊した別字               | 「買」の上部が別字形に               |

**原因**: `ImagePaths` は「そのまま貼るレイヤー」ではなく、画像生成モデルへの**視覚的な参照**として渡る。
モデルは参照を見て**描き直す**ので、プロンプトで「改変するな」と書いても再描画は止まらない。
文字数の多い UI ほど誤字が出る。

**対処（これを守る）**:

- **ストアのスクリーンショットは AI 生成物を使わない。** 実機・エミュレータのキャプチャ
  （`scripts/release/capture-store-screenshots.mjs`）＋ `sharp` での合成だけで作る。
  文字は SVG のテキストとして描くので、寸法も字も決定的に一致する
- 生成 AI を使ってよいのは、**実在の UI を写さない面**だけ — フィーチャーグラフィックの背景、
  帯の装飾、料理・台所のイメージ写真、アイコンの意匠検討
- 生成物を掲載素材に採用するときは、**必ず等倍で拡大して日本語を 1 文字ずつ見る**。
  縮小表示では誤字が見えない（今回も 768px 表示では気付かず、クロップ拡大で判明した）

再現:

```bash
agy --model gemini-3.8-flash-low --dangerously-skip-permissions \
  -p "generate_image の ImagePaths に <実機スクショの絶対パス> を渡し、AspectRatio '9:16' で
      『入力画像を一切改変せず中央に配置し、上部に金色の明朝体でコピーを入れる』と指示して生成。
      生成後、入力の文字と一字一句同じか自分で見比べて列挙すること"
```

## 4. では何に使えるのか（ストア素材との対応）

| 掲載素材                             | 作り方                                                                   | 生成 AI の出番                                        |
| ------------------------------------ | ------------------------------------------------------------------------ | ----------------------------------------------------- |
| スマホ用スクショ 8 枚（1080×2400）   | 実機キャプチャ ＋ `sharp` 合成（既存 `generate-play-promos.mjs` の系統） | **使わない**（§3）。背景の質感だけなら可              |
| フィーチャーグラフィック（1024×500） | `generate-play-promos.mjs`（現行も `sharp` + SVG）                       | 背景画・装飾の素材として。**文字は SVG のまま**が安全 |
| アプリアイコン                       | `scripts/generate-icons.mjs`                                             | 意匠の検討（案出し）に。採用時は SVG/ベクタで作り直す |
| プロモ動画                           | `promo-video` Skill（実機 screenrecord ＋ ffmpeg）                       | **使えない**（動画生成ツールが無い）                  |
| 動画のナレーション・字幕             | —                                                                        | **使えない**（TTS・音声認識とも無い）                 |
| 掲載文 ja/en                         | `listing-{ja,en}.md` ＋ `update-store-listing` Skill                     | 対象外（文章なので Claude 側で書く）                  |

**「動画を AI で作る」は今回はできない。** 動画を刷新するなら、従来どおり実機収録の台本を書き直す形になる。
（本人が Gemini アプリや Flow をブラウザで手作業で使う、という道は別にあるが、それは**利用者の作業**であって
このリポジトリの自動化には載らない。やるなら「ユーザー作業」として §5 の受付票に立てる。）

## 5. 分かったことの要約（症状 → 原因 → 対処）

- **症状**: 生成画像に実機スクショを渡すと、見た目が良いのに UI の漢字が誤字になる（「期限」→「期服」）。
  **原因**: `ImagePaths` は貼り付けではなく生成モデルへの視覚参照で、モデルが描き直すため。
  **対処**: ストアスクショは AI 生成を使わず `sharp` 合成。生成物は必ず等倍拡大で 1 文字ずつ検査する。
- **症状**: 「Omni で動画も作れるはず」という期待が、実物では満たせない。
  **原因**: `agy` のモデル一覧・ツール一覧に動画・音声の生成が無い（画像だけ `generate_image` で提供）。
  **対処**: 動画は `promo-video` Skill の実機収録を前提に計画する。生成 AI を織り込まない。
- **症状**: 生成物の寸法がストア要求と合わない（1376×768 等）。
  **原因**: `AspectRatio` は比率のみで、ピクセル指定のパラメータが無い。
  **対処**: 生成 → `sharp` でリサイズ／トリミング、を必ず 1 セットで扱う。
