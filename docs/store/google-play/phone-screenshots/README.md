# Google Play スマホ用スクリーンショット

Google Play はスマホ用スクショを**最大 8 枚**まで。このフォルダ直下の 8 枚を
この順番でアップロードする。**1 枚目に「献立」、3 枚目に「冷蔵庫からレシピ」
（1.13.1 新機能・短い説明の「冷蔵庫を撮るだけ」訴求と直結）を置き、4〜5枚目で
「写真からレシピ」のストーリー（仕組み→編集可能な下書き）、以降で家族の蔵書・共有を
見せる構成**（1.13.1・2026-09-05 に更新。1.13.0 の並びは下の
「1.13.1（2026-09-05）の入れ替え」、2026-07-14 ASO監査時点の並びは末尾「旧順」参照）。

**機械的な再取得とアップロード**（詳細は `docs/リリース手順.md` §3-2）:

- 取得: `node scripts/release/capture-store-screenshots.mjs`（サンプルデータ入り
  リリース APK ＋ 1080x2400 エミュレータ `daidoko_e2e_fresh_api36` 前提）
  - **撮れた PNG が 20KB 前後なら中身はローディングスピナー。** wipe 直後の初回起動は
    シードとマイグレーションが走り、既定の待ち（7 秒）では描画が間に合わないことがある
    （1.13.1・2026-09-06 の撮り直しで初回 run の複数枚がスピナーだった）。先に一度アプリを
    起動してシードを済ませるか、`--wait 20000` を付けて撮り直す。小さいサイズの
    ショットは必ず目視すること
- 反映: `node scripts/release/update-play-screenshots.mjs`（下表の順にアップロード。
  順序を変えるときはスクリプトの ORDER 配列も併せて更新）
- `08`・`10`・`12` は自動化対象外（manual）— `08` `10` は既存 PNG を維持、`12` の
  撮り方は下の「`12-fridge-to-recipe.png` の撮り方」。手で撮るときも
  ステータスバーは同じデモモードに揃える（`.claude/skills/update-store-listing` §スクリーンショット）
- **調理セッション汚染に注意**（PR #254 の調理セッション以降）: `04` で料理中モードを
  ディープリンクで開くと調理セッションが `app_meta` の `cooking_session` キーに永続化され、
  「完成」を押すまで**タブバー直上に Now Cooking pill** が出続ける。force-stop しても
  次回起動で復元されるため、後に撮る `06` や手動の `10` に pill が写り込む（`07` は
  タブバーを隠す画面なので写らない）。`capture-store-screenshots.mjs` は各ショットの
  起動前と run 終了時に `adb root`＋sqlite3 でこのキーを空にして自動回避する
  （`--shots 04` のように cook 画面で撮り終えても、手動で撮る `08`/`10` に持ち越さない。
  root の効くエミュレータのみ。実機は警告して続行するので、撮影後にアプリで「完成」を押す）。
  pill をあえて見せたいショットを作るときは `--keep-cooking-session` でオプトアウトできる。

### `12-fridge-to-recipe.png` の撮り方（manual・1.13.1）

自動化できない（実際の冷蔵庫写真で AI を 1 回走らせる必要がある）。BYOK を設定して
撮ると無料枠を消費しない。

1. 実際の冷蔵庫（冷蔵室）を撮り、base64 経由でエミュレータへ入れる（`adb push` は
   無言で失敗する — en 版 README「撮るときに踏んだこと」）→ メディアスキャン
2. `daidoko://fridge` → ギャラリーから選ぶ → 読み取り
3. **確認シート（review）の状態で撮る** — 品目リスト＋「たぶん」バッジ（confidence low）＋
   「在庫に追加（n）」が写るのが狙い。品目 8〜12 件・「たぶん」1〜2 件くらいの写真が画になる
4. 撮ったら**「在庫に追加」を押さずに閉じる**（在庫が変わると `05` の献立の理由が変わる）。
   **使った実冷蔵庫写真は、撮影後にエミュレータと作業フォルダから削除する**（生活が写る。
   リポジトリにも入れない）

`05-menu-plan.png` の初回版（1.13.0 のドラフト）は base seed 環境に **在庫を 1 品
（Onion/玉ねぎ・明日期限）だけ手で足して**撮っていたが、これは**訴求として失敗だった**。
Day 1 こそ「Onion is expiring soon」になるが、pantry がほぼ空のままなので Day 2・3 は
`few-missing`（買い足し◯品で済むから）の ◯ が **7〜8** まで膨らみ、「Only 8 things to buy」
という**献立の売り（いまある材料から組む）と正反対の文言**が出てしまっていた
（2026-09-01 レビューで指摘・英語版で発覚）。

**直し方: 3 日分の候補レシピ（肉じゃが・味噌汁・唐揚げ）の材料をほぼ全量、在庫に入れる。**
`missingCount` が 0 に近づけば `coverage`（いまある◯品で作れるから）が勝ち、`few-missing` の
大きい数字が出る余地が無くなる。玉ねぎ・醤油・だし汁は 3 レシピ間で重複するので、
**重複ぶんは行を 2 つに分ける**（1 つは在庫として消費されても、もう片方が別の日に残る）。
最終的に採用した組み合わせ（en / ja、`quantity=1` 固定・`expires_on` は玉ねぎの 1 行だけ翌日）:

### AQUOS → エミュレータの再現手順（2026-08-28 に確立）

1. **AQUOS**: だいどこ → 設定 → バックアップ → 「移行ファイルを作成」。
   保存先フォルダは `Download/daidoko` に**設定済み**なので、押すだけで
   `/sdcard/Download/daidoko/daidoko-transfer-*.daidoko.zip` に自動で書き出される → `adb pull`
2. **エミュレータへ**: `adb push` は無言で失敗するので base64 で流し込む
   （`base64 -w0 zip | adb shell "base64 -d > /sdcard/Download/x.zip"`。md5sum で照合）
3. **復元**: `daidoko://backup` → 「移行ファイルから復元」→ ピッカーで Downloads から選ぶ。
   **エミュレータのシードは置き換えられる**（それが目的）
4. **AI 無料枠も復元される**ことに注意 — AQUOS で消費済みなら `07` が「あと 0 回」になり、
   `08` の AI 実行もできない。エミュレータは `adb root` が効くので直接戻す:
   `sqlite3 /data/data/com.daidoko.app/files/SQLite/daidoko.db
"UPDATE app_meta SET value='0' WHERE key='ai_photo_recipe_free_lifetime_used';"`
   （キーは `src/services/usage.service.ts`。アプリを force-stop してから）

### 撮り直すときに要ること

撮り直すなら**実データが要る**。シードには料理写真が 1 枚（`scrambled-egg.jpg`）しか無く、
**このアセットを差し替えると本番のシードが変わる**ので触らないこと。上の再現手順どおり
**機種変更バックアップを復元する**のが最短（「写真からレシピ」で 6 品を作り直すと AI を 6 回消費する）。

どの画面がどの料理か:

| ショット | 料理                                                                           |
| -------- | ------------------------------------------------------------------------------ |
| `02`     | 6 品すべてが一覧に並ぶ                                                         |
| `03`     | マッシュルームとベーコンの詰め物アヒージョ                                     |
| `04`     | 牛肉のカルパッチョ（ヘッダのレシピ名のみ。**料理中モードに表紙写真は出ない**） |
| `08`     | 牛肉のカルパッチョの写真から AI が作った下書き                                 |
| `10`     | 牛肉のカルパッチョ（ヒーロー）                                                 |

`08` の下書きを**保存すれば** `10` の表紙は自動で付く — `getRecipeDetail` の
`heroPhotoUri` が `coverPhotoPath ?? 最新の調理記録の写真` に落ちるため。
写真取り込みは表紙ではなく**調理記録**として写真を保存している。

エミュレータは 1080x2400、AQUOS 実機は 1080x2432 なので**混ぜられない**
（`update-play-screenshots.mjs` が寸法の混在を弾く）。片方に寄せて 8 枚とも撮ること。
