# 勝つための機能（2026-08-27 の調査）

> 勝っている競合のレビュー **687 件**を実際に読み、機能表と定着の仕組みを採掘した結果。
> 検証役が引用約 50 件を生データと突合し**捏造ゼロを確認済み**（軽微な指摘のみ）。
> 前提の症状と勝ち筋は `なぜインストールされないか-2026-08-26.md` / `無料の露出チャネル-2026-08-27.md`。

## 結論 — 上位 3 つ

**「入る理由（献立=検索語）・戻る理由（通知）・思い出す理由（ウィジェット）」を揃える。**

### ① 献立 #215 M1（AI 無し版）— 最優先・4〜6 日

**レビュー・検索語・機能表の 3 方向すべてが指す唯一の機能。**

- **課金理由になることを競合の解約レビューが証明している。** クラシル 221 件中
  「献立」言及 **61 件**。2024 年の献立改変で
  「献立作成機能と買い物メモの機能が便利でずっと有料プランで使っていた…解約しました」
  （1★ 2024-08-17）型が **24 件**
- 「献立アプリ」は実検索語（Apple サジェスト実測。「AI レシピ」は検索されていない）
- レピッタ 5★「レシピを登録する→1週間分の献立を立てる→買い物リストも作成…
  **全ての過程がひとつのアプリで完結**」— **だいどこが献立を足した瞬間に成立する文章**
- クックスルーにも自発要望（「自動で1週間の献立考えてくれる機能とか」3★ 2025-10-15）
- クラシルの教訓: **「保存レシピ→献立に追加」の動線を壊すと解約される**。
  最初から蔵書庫起点で作る（#215 の設計はそうなっている）

**M2（AI 並べ替え）の実装設計は `買い物リスト・在庫設計.md` §10.10 に確定済み（2026-08-27）。**

### ② 賞味期限のプッシュ通知 — 2〜4 日・献立の次

- **両巨頭が数年放置している頻出要望**: リミッター「半年前、1年前の通知もあると
  助かります」(4★ 2024-09)・マイくら「現状最大3日前…数ヶ月前まで設定できると嬉しい」
  （役立った 24 件）。リミッターは一括設定のみ・マイくらは最大 3 日前のまま
- **通知の信頼性が 1★/アンインストールの直接原因**: リミッター 1★「通知が一切来ません。
  …アンインストールを決めました」・「使い切ったのに通知が来ます」
  → 勝負は文面ではなく**「約束した通知が確実に来て、在庫と同期していること」**
- 検索語「賞味期限管理アプリ」の 1 位機能を、だいどこは持っていない（記録のみ）
- **#200 の「通知疲れを踏まない」方針と矛盾しない**: オプトイン＋品目別リード日数は、
  まさにローリングストック利用者がレビューで求めている形

### ③ Android 買い物リストウィジェット — 2〜4 日・上 2 つの後

- **競合ゼロ**: 勝者 6 アプリの掲載文・公式サイトに「ウィジェット」**0 件**（grep 確認）
- Play は 2025-03 からウィジェット検索フィルタ・バッジ・特集がある＝**露出面**
- マイくらの掲載文冒頭は「スーパーで買い物をしている時に、家の冷蔵庫に何が余っていたか
  確認したいことは？」— **店頭の瞬間の钩**そのもの。家族同期済みの買い物リストは
  glanceable 表示の典型
- 実装は react-native-android-widget（Expo config plugin 対応）。**iOS はやらない**
  （expo-widgets は公式が "currently in alpha"）
- **継続率への効果の独立データは無い**（Gratitude +25% はベンダー自己申告）。
  効果測定前提。**prebuild が絡むので Apple Ads 投下と同時進行にしない**
  （keyboard-controller で 3 回壊れた前例）

## やらない方がいいこと

| 案                                   | 理由                                                                                                                  |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| 毎日型のおすすめレシピ通知           | 毎日配信を成立させているのは特売・チラシという毎日更新の外部データ（デリッシュ毎日10時）。レシピだけでは週次行動      |
| iOS ウィジェット（今は）             | expo-widgets は alpha。審査初期の iOS に載せるリスクに見合わない                                                      |
| **基本操作への広告・件数ゲート追加** | **1★ の量産機**: リミッター「1つ登録する度に2つの動画広告」・クックスルー「30個までって知らんくて…**先言え**」        |
| カロリー・栄養計算                   | クックスルーが無料側で既に持つ。要望 3 件どまり・工数大                                                               |
| レシピ配信・横断検索への進出         | クックパッド/クラシルと正面衝突。クラシルでは素人レシピ混入自体が解約理由。**「自分の蔵書」側に留まるのが構造的優位** |
| Apple Watch / App Intents            | レビュー 707 件中、言及ゼロ                                                                                           |

**AI 無料枠を月 N 回に変えるときは、上限を画面に先に明示すること**（「先言え」型 1★ の予防）。

## レビュー採掘で分かった、機能以外の教訓

- **データ消失が最大の 1★ 要因**（リミッター 114 件中 15 件超）。
  「災害用のローリングストックのデータが全部消えた」— だいどこのバックアップ強化
  （週次スナップショット・SAF 書き出し）は**正しい投資だった**
- **共有は「あれば完璧」枠**（リミッター 7 件）。「夫婦で共有が出来ればこれ以上ないくらい
  便利」— アカウントレス家族同期は競合が持たない実装済みの武器
- **値上げの恨みは長い**（クックスルー 100→280→400 円で 2★「値上げが多過ぎました」）。
  「まずは赤字にならない低め」で出して**上げるより、最初から据える方が傷が浅い**。
  買い切り要望も一定数ある（5★「多少高くてもいいのでサブスクではなく買い切り版を」）
- **マイくら（食材管理 1 位）には専用の買い物一覧画面が実質無い**（要望 3 件）。
  在庫⇄買い物の接続は、1 位の弱点でもある
