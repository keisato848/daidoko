# 広告にお金を出すか（2026-08-27 の調査）

> 「1000 円くらいなら広告出してもいい」への答え。**結論: その 1000 円は使わない。**
> ただし **Apple Ads の $100 無料クレジット**という別の枠が見つかった。
> 3 観点＋敵対的検証で調べた。**検証で潰れた主張は落とし、確認できた出典だけ残す。**

## 用語（毎回混同するので先に）

|                                             |                                                 |
| ------------------------------------------- | ----------------------------------------------- |
| **AdMob**                                   | 広告を**出して稼ぐ**側。既にアプリに入っている  |
| **Google Ads アプリキャンペーン**（旧 UAC） | 広告を**買って宣伝する**側。別サービス          |
| **Apple Ads**（旧 Apple Search Ads）        | App Store の検索面に出稿する。2025-04-14 に改称 |

## 結論 1: ¥1000 では、どの媒体でも何も買えない

| 媒体       | 壁                                                                                                                          | 確度                          |
| ---------- | --------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| Google Ads | **「1 日の予算は目標 CPI の 50 倍以上」が現存**。日本の非ゲーム実用アプリの CPI は数百〜数千円 → 必要な**1 日**予算が数万円 | 一次・公式 4 ページで重複確認 |
| TikTok     | 公式に**最低 $50/キャンペーン・$20/広告グループ**                                                                           | 一次                          |
| Meta       | 絶対額の下限を公表していない（本文が JS で読めず**記載有無は不明**）                                                        | 取得できず                    |
| X          | **「最低出稿額なし」と公式明記**。金額の壁だけは無い                                                                        | 一次                          |

Google の 50 倍ルールは[一部ページでは「推奨」ではなく「**必要があります**」](https://support.google.com/google-ads/answer/14104492?hl=ja)と書かれている。
**2026-07 の「見送り」判断は今も正しい。**

### 買っても効かない理由（金額とは別に）

- **母数が無い。** Google はユーザー離脱率・DAU/MAU を挙げるが、
  **「十分な数のユーザーがインストールし利用している必要がある」**という前提を自ら明記している。MAU 3 では良くも悪くも動かない
- **「最初のインストールを買って弾みをつける」に実証は無い。**
  burst campaign を語っているのは、それを**売っている業者**のブログだけだった。
  「インストール速度が最強のランキングシグナル」は Google の公式ランキング解説に出てこない
- **評価 0 件の掲載ページに有料クリックを送るのは、買ったクリックを捨てる行為**

## 結論 2: Apple Ads に $100（≒1.6 万円）の無料クレジットがある

[Apple 公式ヘルプ](https://ads.apple.com/app-store/help/billing/0032-apple-ads-promo-credit)の逐語:

> "we automatically give you a $100 (U.S.) credit to try it for free"
> "**If you link a campaign group instead of your top-level account, the credit won't be applied.**"

- **一度きり**・新規アカウントのみ。USD 以外の通貨は Apple の日次レートで換算
- 適格条件 =「App Store Connect の登録アカウントホルダー」＋「販売中のアプリが 1 本以上」
  → **クリア済み**（App ID `6800964382`・1.11.0・Food & Drink・2026-08-22 公開・評価 0 件）
- **Basic でも使える**。[Basic のページ](https://ads.apple.com/app-store/basic)に
  "Try Apple Ads for free with a 100 USD credit" と明記（検証役が「未確認」としていた点）
- Basic は**インストール課金・月予算に上限が効く**。Advanced はタップ課金・**予算上限なし**

## 住所は公開されない（Play のときとは違う）

**これが今回いちばん確かめたかった点。** 課金を諦めた理由が住所公開だったため。

- **Apple Ads の広告リポジトリ（EU DSA 39 条対応）が公開するのは氏名レベルで、住所欄が無い。**
  DSA 26 条・39 条が求めるのも「自然人又は法人」＝ identity であって住所ではない
- **そもそも EU/英国のストアにこのアプリが無い**（`itunes.apple.com/lookup` で
  de/fr/ie/gb がいずれも `resultCount=0`・jp/us のみ 1。2026-08-27 実測）。
  Apple Ads は「そのストアで入手可能」でないと出稿できないので、**リポジトリに載る経路が無い**
- App Store 製品ページに住所が出る本当のトリガーは Apple Ads ではなく
  **DSA の取引者(trader)要件**（30・31 条）。EU 配信をしない限り引かれない

**ただし二段に分けて理解する**:
**Apple には自宅住所を登録する**（「事業が法的に登録され、税務上の居住地とされる住所」＝
事業所の無い個人には自宅）。**公開はされない**が、「絶対に公開しない」という明文の保証は取れていない
（規約に「Apple は情報を公表または開示する義務を負う場合がある」という包括条項が実在。住所への言及は無い）。

## 開業届は、この問題の解ではない（重要）

自然に「開業届を出せば Tax ID 欄が埋まる」と考えたくなるが、**事実として誤り**。

- **開業届を出しても番号は交付されない。** 所得税法 229 条の「届出」であって、それだけ
- **法人番号は個人には永久に出ない。** 指定対象は国の機関・地方公共団体・設立登記法人等のみ
- 個人が持ちうる唯一の tax ID は**インボイスの登録番号(T+13 桁)**だが、
  **課税事業者**が登録して初めて通知される。免税事業者は持っていない

→ **転職活動中に開業届を出す必要は無い。** 仮に Tax ID が必須で弾かれた場合、
残る道はインボイス登録（＝消費税の納税義務を負う）だけで、**$100 のための代償として割に合わない。
そのときは撤退が正解。**

**マイナンバーは絶対に入れない。** 番号法 15 条（提供の求めの制限）・20 条（収集等の制限）が
法定の場合を除いて「何人も」求めること・収集することを禁じている。広告出稿は該当しない。

## 日本は Tax ID 必須国に入っていない

Apple は tax ID の提出を**規約の条件として課す国を名指しで列挙**している
（[Tax Obligations and Requirements](https://ads.apple.com/taxes)）。

| 国       | 要求                                                            |
| -------- | --------------------------------------------------------------- |
| インド   | GST 登録番号が**必須**                                          |
| 韓国     | Korean Tax ID を提供する**義務**                                |
| 台湾     | 統一編号                                                        |
| **日本** | **JCT が iTunes K.K. の請求書に乗る、とだけ。番号の要求は無い** |

**2026-08-27 に日本語版 https://ads.apple.com/jp/taxes を全文確認した結果、
番号の提供を求められている国は 8 つ**（オーストラリア ABN / ブラジル / コロンビア NIT+RUT /
インド GST / ニュージーランド事業者番号 / フィリピン TIN / 韓国 事業登録番号 / 台湾 統一編号）。
**日本はこの 8 か国に入っていない。** 日本の項は逐語で:

> お客様が日本の居住者であるか、日本に所在している場合、本サービスが iTunes 株式会社によって
> 提供される場合を除き、サービス規約に基づき本サービスについて支払われるべき日本の消費税に対する
> リバースチャージ方式の採用に同意していただくものとします。（後略）

**課税方法の話だけで、番号の要求は一言も無い。**
Apple が「必要な国では名指しで書く」運用をしている以上、これは有意な沈黙。
ただし**沈黙は保証ではない**（法的義務が無いことと、フォームが空欄を通すことは別）。

## 唯一の未確認点と、確認の最短手順

**サインアップ画面の Tax ID 欄が必須か任意か。** Apple のヘルプは
[商取引詳細の 4 項目](https://ads.apple.com/app-store/help/get-started/0004-set-up-an-account)
（Legal entity name / Business entity status / Tax ID / Address）を列挙するだけで、
**必須・任意を書き分けていない**（日英両ロケール・/taxes・規約を読んだ上での「書かれていない」）。

日本語版の設定ページも確認したが、4 項目を列挙するのみで**必須／任意の表示が無い**（逐語）:

| 欄               | Apple の説明（逐語）                                                           |
| ---------------- | ------------------------------------------------------------------------------ |
| 法人名           | 「定款および／または納税申告書に記載された、会社の登録名。」                   |
| 法人のステータス | 「…**個人事業主の場合は「いいえ」を選択します**。」                            |
| 税金 ID          | 「ビジネスの関連する税務登録証明書に記載されている会社の税金 ID 番号。」       |
| 所在地           | 「会社が法的に登録されており、税法上の居住法人であると見なされている所在地。」 |

**個人事業主が想定利用者であることは明記されている**（法人のステータス欄）。
一方で**登記していない個人が法人名・税金 ID に何を入れるかは、どこにも書かれていない**。

**確認手順**: Apple Ads **Basic** からサインインし、
**商取引詳細の画面が出るか / 税金 ID 欄に必須マークが付いているか**を見る。
→ 手順の詳細は `docs/browser-tasks-apple-ads.md`。

### 順番を間違えないこと

**Basic → 駄目なら Advanced。逆は不可。**
「Advanced を作りかけて途中で Basic に切り替えようとするとエラーになる」と Apple が明記している。
予算管理の面でも Basic が安全側（月予算に上限が効く・CPI 課金 vs Advanced は予算上限なし）。

### 入力欄への答え

| 欄                     | 入れるもの                                         | 根拠                                                             |
| ---------------------- | -------------------------------------------------- | ---------------------------------------------------------------- |
| Business entity status | **いいえ**                                         | 一次。日本語ヘルプに「個人事業主の場合は『いいえ』を選択します」 |
| Legal entity name      | 法的氏名（App Store の販売元 `Kei Sato` と揃える） | **推論**。Apple Ads 側に個人向けの明示は無い                     |
| Tax ID                 | **空欄で進めてみる**                               | 二次（体験談 1 件）＋上記の沈黙                                  |
| Address                | 自宅住所                                           | 公開されない（上記）                                             |

### 「駄目なら 30 分で撤退」ではない

アカウント作成は**規約への同意＋法的氏名・住所・カード情報の登録**を伴う。
規約に「正確・最新・完全な情報（住所、支払情報、**関連する税務情報（納税者番号や証明書等を含む）**）を
提供することに同意する」という条項が実在する。
**作成後に Apple が事後的に番号提出を求めてくる経路は、確率は不明だが存在する。**

## $100 で何が得られるか — **数字の裏付けは無い**

**この節の見積もりに一次情報は無い。** 実効性を調べる担当エージェントが API エラーで落ち、
日本の App Store の獲得単価に一次資料で当たれていない。オーダー感として読むこと。

- 単価が数百円なら**百件台**、千円台なら**十数件**。**数十〜百数十件**の幅
- **継続はしない。** 一度きりで、使い切れば元の流入に戻る
- 期待値は「$100 で流れを変える」ではなく「**母数の初速を買い、評価を数件付ける**」まで

**順序**: 評価を数件付けてから使う方が $100 の価値は上がる（広告の着地先が評価 0 件だと CVR が落ちる）。
クレジットの**有効期限は未確認**なので、期限が緩いなら評価が先。

5. **クレジットの有効期限**

## 調査の作法（今回の反省）

- **担当エージェントが 1 体落ちた**（API エラー）。その観点＝実効性の数字は**空白のまま**。
  落ちたことを書かずに他の数字で埋めると、裏付けの無い見積もりが事実になる
- 検証役が**虚偽の記述を 1 件検出**した（「Basic 専用のヘルプは 1 本も無い」→ 実際は 6 本ある）。
  そこから導かれた「Advanced 一択」の推奨ごと落とした
- **「URL は挙がっているが中身が違う」が前回に続き再発**（CPI レンジ ¥100〜1000 の出典 2 本とも
  その記述が無かった）。引用は必ず開いて逐語で確かめる
