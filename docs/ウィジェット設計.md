## 1. 背骨: 共通スナップショット JSON・DB 直読みしない

`widget-snapshot.service.ts`（新設）が JSON 1 本（version/writtenAt/locale/shopping/menu）を組み立て、iOS は `ExtensionStorage`（App Group UserDefaults）＋`reloadWidget()`、Android は `documentDirectory/widget/snapshot.json`＋`requestWidgetUpdate()` へ書く。書くタイミングは買い物書き込み系・献立保存・調理記録保存・**同期 pull 完了後**・background 遷移の 5 フック（500ms デバウンス）。

DB 直読み（iOS App Group への DB 移動 / Android Headless からの expo-sqlite）は両案とも落とす — 既存全ユーザーの DB ファイル移動はデータ消失リスクの新設であり、表示に要るのは高々 10 行。

**検証反映**: 初稿の「スナップショットをクラウドバックアップ除外に足す」は**不要（no-op）** — `withDaidokoBackupRules` のクラウド規則は include 方式で documentDirectory は最初から対象外。D2D 移行では運ばれるが派生データなので無害（除外作業は書かない）。

## 4. リスクと切り離しやすさ

- iOS: EAS の CNG 拡張ターゲットは Expo 公式が **experimental** と明記・`@bacons/xcode` は alpha.32。**検証反映 2 件**: ①5.0.0 の内部依存に `@expo/prebuild-config ~55.0.6`（SDK 55 世代）が入っており、**SDK 54 で prebuild が素直に通るかを W1-i 初手のスパイクで確認**。②**Mac の要件確認（macOS 15 Sequoia / Xcode 16 / CocoaPods 1.16.2）**を着手前チェックに追加 — 満たさないと EAS クラウド往復のみの開発になり工数前提が崩れる
- Android: ランチャーのサイズ報告ズレ→クロップ（公式明記）は余白 8dp+ で吸収
- **切り離し性（R5 実装後の実態・2026-08-29 レビュー指摘で更新）**: 消すのは **3 点セット** —
  plugin（app.json）・`src/widgets/`・**`widget-snapshot.service.ts` の `pushToAndroidWidget()`**。
  当初「スナップショットサービスだけ残せば無害」としていたが、即時反映（設計 §1 の
  `requestWidgetUpdate()`）の配線が `src/widgets/` を動的 import しており、ディレクトリだけ
  消すとビルドが壊れる。実行時は try/catch で守られているが、**ビルド時の欠落は別**
- 審査: 両ストアとも標準機能・追加申告なし。データは端末内完結（個人情報の線・同期 §0-2 に抵触ゼロ）

## 7. R5 Android スパイクの結果（2026-08-29・実測）

**§6-1 の答え: 読める。フォールバック不要。**
Headless タスクから `expo-file-system/legacy` で `documentDirectory/widget/snapshot.json` を
読めることを emulator-5554 で確定（logcat: `WIDGET_ADDED snapshot: remaining=19`）。
ウィジェット表示 → タップ → `daidoko://shopping` → 買い物リスト画面まで一気通貫を確認。

実機まわりの発見（症状 → 原因 → 対処）:

- **`adb shell cmd appwidget` は使えない**（AQUOS・エミュレータとも "No shell command
  implementation"）→ ウィジェットの配置はランチャーの長押し → Widgets → アプリ行を展開 →
  **プレビューをタップして出る「+ Add」ボタン**で追加できる（ドラッグ不要）
- **`adb shell input text` は日本語で NullPointerException** → テストデータは
  シードのチェックボックス操作で代替する
- **AQUOS は暗証番号ロック中はスパイク不可**（screencap 真っ黒・既知）。arm64 APK は
  インストール済み・起動確認は未了 → **1.13.0 の一括実機検証（#243）でロック解除の上で確認**
- `build-android.mjs` は既定 arm64-v8a。**エミュレータには `--arch x86_64` で組み直す**
  （arm64 をエミュに入れると SoLoader UnsatisfiedLinkError で即クラッシュ）
