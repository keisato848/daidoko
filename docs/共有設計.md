# 共有設計 — 「誰に見せるか」で束ね直す

> 作成 2026-09-03。きっかけは利用者の連続した指摘:
> 「リンクによる共有が非常に使いづらい。OS共有でLINE等で共有できなかったか」
> 「誰に共有しているか把握できないのか」「共有方法と、今何が誰に共有されているのかが分かりづらすぎる」
> 「（対症療法の管理画面に対し）そんな単純か？共有は設計見直し必要では？」
>
> 本書は**共有の UX 全体**を束ねる設計。仕組みの詳細は従来どおり
> `docs/Web共有設計.md`（リンク公開の実装）と `docs/クラウド同期設計.md`（家族グループ同期）が正で、
> 本書はその**上に載る利用者向けの見せ方**と用語を決める。

---

## 1. 現状の棚卸し（2026-09-03・1.13.0 時点）

共有と呼べる仕組みは 4 つあり、**入口・画面・用語がすべて別**。

| 仕組み                   | 誰に見えるか                               | 入口                                  | 状態の置き場所                      |
| ------------------------ | ------------------------------------------ | ------------------------------------- | ----------------------------------- |
| テキスト共有             | 送った相手（取り込み書式で往復可）         | レシピ詳細メニュー「共有」            | なし（送りっぱなし）                |
| リンク公開（レシピ単体） | **URL を知る全員・無期限**                 | レシピ詳細メニュー「Webページで共有」 | app_meta（1.13.0 まで一覧手段なし） |
| リンク公開（帖）         | URL を知る全員（パスコード・期限は帖のみ） | 帖編集 / 設定→データ→レシピ帖         | recipe_books.share_url              |
| 家族グループ同期         | **グループのメンバーだけ**                 | 家族グループ画面・設定→クラウド同期   | secure-store ＋ サーバー            |

さらに買い物・在庫は品目ごとの「自分だけ」トグル（既定=共有）が各品目画面の奥にある。

## 2. 何が歪んでいるか

1. **機構中心 vs 相手中心。** 利用者は「妻に送りたい」「友達に見せたい」で考えるが、
   UI は仕組みごとに入口を分け、利用者に仕組みを選ばせている。
   「リンク共有が使いづらい」の正体。OS 共有シート自体は全経路に実装済みで、
   足りないのは機能ではなく**編成**。
2. **可視範囲が共有の瞬間に明示されない。** リンク=全員・無期限、グループ=メンバーのみ、
   という重大な差が、発行ボタンを押す瞬間に一度も表示されない。
   「誰に共有しているか把握できない」の本体は管理画面の不在より先にこれ。
3. **用語の揺れ。**「共有」「Webページで共有」「Web共有リンク」「共有グループ」「公開」が混在。
   同じ「共有」がテキスト送付とリンク公開と同期の 3 つを指す。
4. **全体を束ねる場所が無かった。** 設計書も Web共有とクラウド同期に分かれ、
   共有の全体像はグループ作成ダイアログの 2 文でしか語られない。

裏づけ: ペルソナ点検 `docs/reviews/persona-help-home-2026-09-03.md` P4（誰の記録か分からない）、
本書冒頭の利用者指摘 4 件。

## 3. 再設計 — 決定事項

### 3-1. 共有は「相手」で 2 つに再編する

利用者に見せる区分はこの 2 つだけにする:

- **家族と共有** — グループの端末どうしで自動同期。**メンバーだけに見える**。
- **リンクで渡す** — Web ページを発行して OS 共有シートで送る。**リンクを知る人は誰でも見られる**。

テキスト共有は「リンクで渡す」シート内の副項目（「テキストで送る」）に格下げする。
仕組み名（Web共有・クラウド同期）は利用者向け文言から消し、設計書内の用語として残す。

### 3-2. 統一共有シート

レシピ詳細・帖・買い物などの「共有」アクションはすべて同じボトムシートを開く:

```
このレシピを共有
● 家族と共有          … 参加済みなら「共有中（グループのメンバーだけに見えます）」
                        未参加なら「家族グループをつくる/参加する」へ
● リンクで渡す        … 「リンクを知っている人は誰でも・いつまでも見られます」
                        [リンクを発行して送る]（発行済みなら [送る] [停止]）
○ テキストで送る      … 取り込み書式のテキストを共有シートへ
```

**可視範囲の 1 行は必ず表示する**（グレーの注記でよい。省略不可）。

### 3-3. 状態の一元化 —「共有の管理」

設定 → データ → **共有の管理**（1.13.1 で追加済み・share-status.tsx）を共有状態の正面にする:
家族グループの参加状態と共有範囲の常設表示・リンク公開中の一覧（単体＋帖件数）・
「自分だけ」品目の件数。帖の一覧は既存管理画面へ送る（一覧の二重化はしない）。

### 3-4. 用語統一表

| 使う                          | 使わない（廃止・設計書内のみ）     |
| ----------------------------- | ---------------------------------- |
| 家族と共有 / 家族グループ     | クラウド同期（利用者向け文言から） |
| リンクで渡す / リンクで公開中 | Web共有・Webページで共有           |
| テキストで送る                | 共有（単独で機構を指す用法）       |
| 自分だけ                      | 非公開・プライベート               |

### 3-5. やらないこと

- **閲覧者の個人追跡はしない。** リンクの閲覧者をサーバーに記録しない方針
  （`docs/Web共有設計.md` §0-2 の通信の秘密の整理）は維持する。「誰が見たか」は
  アカウント制とセットの別機能であり、本再編のスコープ外。
- 家族グループの複数化・役割（閲覧のみ等）は扱わない（需要が観測されてから）。
- 単体レシピへのパスコード・期限の追加は今はしない（必要なら帖を使う導線を出す）。
